# 升级指南

> **一句话：换的是共同底座，不动任何一个人的学科AI大脑。**
> 流程、白名单与失败回滚的**唯一权威定义**在 `commands/upgrade.md`。本文件只写学生和教师各自要做什么。

## 双层隔离（一张表看懂）

| 层 | 内容 | 升级时 |
|---|---|---|
| **模板层** | `skills/` `commands/` `AGENTS.md` `docs/` `examples/` `Home.md` 模板区 `VERSION` `CHANGELOG.md` `LICENSE` `ATTRIBUTION.md` | ✅ 可替换 |
| **数据层** | `raw/**`（全部）`wiki/**`（全部，含 `wiki/practice/` 实践记录）`config.md` `Home.md` 静态清单 | 🚫 **永不覆盖** |
| **校本数据** | `docs/本馆资源获取指南.md`（馆员填写） | 🚫 **永不覆盖**：不在升级源中 |

## 学生怎么升级

1. 从**图书馆版本页 / GitHub Releases** 获取新版 `我的学科AI大脑_v2.00.zip`
2. 把它解压到**当前项目文件夹之外**的同级目录，例如 `../我的学科AI大脑_v2.00/`
3. 说「**升级**」，并告诉 AI 解压后的路径；不填路径时按上一条的默认位置查找
4. AI 自动跑：确认升级源 → 升级前体检 → 备份 `config.md` → 只替换白名单 → 更新版本号 → 升级后体检
5. 看报告：「换了哪些 / 没碰哪些 / 需要你做什么」

> ⚠️ **不要**把新版直接解压覆盖当前项目。升级源目录只被读取，AI 不会往里写东西。
> 你的笔记、课件、个人设置都不会丢。报告会用文件 hash 证明 `raw/` + `wiki/` + `config.md` 前后一致。

**关于版本号告警**：升级按约定跳过 `config.md`，所以 `config.md` 里的 `version` 会落后于 `VERSION`。这不是错误，体检会标为「预期告警」并提示核对 `CHANGELOG.md`，不要求你手改（见 `config.md`「version 与体检告警」小节）。

## 图书馆怎么发新版与保管版本

**发布**：

- 按 `docs/FEEDBACK.md`「版本变更议题表」的双方决议决定是否升版；不因课程资料或资源单更新而升 `VERSION`
- ZIP 文件名带版本号；`CHANGELOG.md` 用大白话写「改了什么、你要做什么」
- 生成 hash 清单，发布到校内固定版本页与 GitHub Releases（ZIP 作 Release 附件、tag 用版本号）；旧版整体归档并记录保留期限
- `docs/材料准备指南.md` 与 `docs/图书馆资源服务指南.md` 随 `docs/**` 白名单升级带入；`raw/` 与 `wiki/` 永不覆盖
- `docs/本馆资源获取指南.md` 是校本数据，**不在升级源中**，升级不覆盖、不删除；由图书馆自行维护
- 反馈**只回写底座或 `config.md` 默认值**，不按课程/院系/班级开分支；不收集学生笔记内容
- 期末匿名反馈与教师使用情况反馈用 `docs/FEEDBACK.md`

**保管清单**：每版留存 ZIP、版本号、发布日期、`CHANGELOG.md`、hash 清单、上一版归档路径与保留期限。

**发版前演练**：拿一份旧副本和一份新 ZIP 真实走一遍「升级」，确认 `raw/` + `wiki/` + `config.md` hash 未变、`Home.md` 静态清单未丢、本馆资源获取指南仍完好（验收项见 `docs/ACCEPTANCE.md` G、K 节）。

**学生侧**：教师不再发 ZIP。学生从版本页主动获取，想升才说「升级」；升级流程以 `commands/upgrade.md` 为唯一权威。

## `Home.md` 为什么不会丢内容

`Home.md` 用**两对**区块标记分隔：

```
<!-- TEMPLATE:START --> ... 可替换 ... <!-- TEMPLATE:END -->
```

当前 2 处模板区：「说人话就能用」命令表、「可选增强」块。标记**之外**的静态清单（课程名、概念链接、个人薄弱点）属于数据层，升级不碰。

## 页面格式变了怎么办

`CHANGELOG.md` 会给出迁移说明。学生看过升级报告后**主动**说「**迁移**」，AI 才按 `commands/migrate.md` 调整 `wiki/` 页面格式，且必须学生确认。

> 「唯一允许触碰数据层的例外」指的是 **`wiki/` 已有页面的 frontmatter 结构**，只由「迁移」执行。升级流程把 `config.md` 备份为 `config.backup.md` 属于写入项目根目录的维护动作，不覆盖学生设置，也不触碰 `wiki/`。

## 失败与自检

任一步失败即停止并回滚，不留下半个升级状态。随时说「**体检**」检查配置合法性、底座完整性、版本兼容性与数据层未被污染；回滚细节见 `commands/upgrade.md`「失败处理」节。

维护是否健康，按 `docs/ACCEPTANCE.md` G、K 节勾选判断。
